Worked example · one node, one document

A MAUDE report count is not an event count.

This page is not written. It is answered. Every claim below came back from a KouroB node that was built from one markdown file, asked the question in the open, and charged for the answer. The event id under each claim resolves to a heading in that file, and the receipt id resolves to a signed record in the node's ledger, which your browser checks at the bottom of this page.

How this page was produced

Three commands, the same three in every KouroB node's README, plus an exporter that asks the built node every question and writes down what it got. 

# build the node, ingest the document, compile a page per heading
kourob init examples/maude-method-node --scope "the MAUDE distinct-event method and what its numbers may claim"
kourob ingest examples/maude-method-node/source --from-markdown --node examples/maude-method-node
kourob loop run compile --node examples/maude-method-node

# ask it anything it holds
kourob query "what is the-acceptance-floor" --node examples/maude-method-node

# rebuild this page's data from a fresh node
uv run python examples/maude-method-node/export_site.py --out site/maude.json

The exporter builds the node in a temporary directory every time, so nothing on this page is read out of a stored build. If the source document changes and the export is not rerun, the page does not quietly drift: it still shows the run it was generated from, timestamped, with the event ids that run actually cited.

Verify it yourself

The export carries each ledger record as the exact bytes it was signed over, plus its signature. Your browser decodes the public key out of the node's did:key, checks every signature with WebCrypto, and walks each record's prev back to the genesis anchor. Then break one on purpose and watch the chain fail from there on.

What this page does not do

  • It is static. The node ran when the export ran. A static page cannot answer a new question, so the questions are fixed and the answers are the ones that run got. Serving live queries needs the HTTP transport, which is not built.
  • Every answer here is T0. A mined rule binds what is <topic> to a stored note, which is why each one costs a scan and cites exactly one event. Nothing on this page exercises the distilled model at T1 or the frontier tier at T3.
  • No FDA data has been processed. The node holds the method, not a run of it. Precision and recall in "the acceptance floor" are design targets, not measured results, because the hand-labelled validation set does not exist yet.
  • One heading, one claim. The gate keys note.v1 on topic and timestamp, so a second paragraph under the same heading arrives as a contradiction of the first and is quarantined. The source document is written around that, and the limitation is filed rather than hidden.
