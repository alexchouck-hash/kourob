# Decisions, week of 2026-09-08

Decisions too small for an ADR, per `AGENTS.md` section 7. Append-only.

## 2026-09-09 · M0 · decisions made without asking

Recorded under `docs/DEFAULTS.md` ("choose, record, continue"). Each is reversible.

1. **M1 acceptance tests are `xfail(strict=True)`, not plainly failing.** The brief asks
   for the M1 acceptance tests as failing tests (section 16 step 6) *and* for CI green on
   M0 (section 12). Strict xfail satisfies both: the tests are red, CI is green, and the
   marker cannot survive the feature landing, because an unexpected pass is a failure.
   Written into `docs/DEFAULTS.md` under Tests. Reversible in one line if the human wants
   them plainly red.

2. **The AGENTS.md section 4 rails are pytest tests, not CI grep steps.** Brief section 9
   says CI greps for them. Making them tests means they also run locally before the push,
   and they gain readable failure messages. CI runs them in the `pytest` step, so the
   enforcement is unchanged. See `tests/test_rails.py`.

3. **`typer` for the CLI.** Not named in the brief. Permissive, small, generates the
   `--help` that M0 is measured on. Under the `docs/DEFAULTS.md` dependency rule, so no
   ADR. `duckdb` and `pyarrow` exceed the 5 MB rule but are named in brief section 9 and
   decided in ADR-0001, which is the ADR that rule asks for.

4. **Unimplemented CLI commands exit 2, not 0.** Stricter reading, per DEFAULTS.md
   ("choose the stricter reading"): a script that calls a stub should fail loudly rather
   than appear to succeed. Each prints its milestone and the brief section.

5. **Every module carries `__milestone__`.** Enforced by `tests/test_rails.py`. It makes
   the tree self-describing and keeps `--help` honest as modules land.

6. **The rail on `data/silver` and `data/gold` is "no module but `gate.py` names the
   path"**, which is stricter than "no module but `gate.py` writes it" and much easier to
   check. Readers go through the `Store` interface by logical table name (ADR-0001).

7. **`bd`'s managed block lives in `AGENTS.md`, not `CLAUDE.md`.** The brief specifies
   `CLAUDE.md` as a one-line pointer. `bd init` appended to both and duplicated itself
   under a second marker; the duplicate was removed and `AGENTS.md` section 9 records that
   section 2 wins where the two protocols disagree.

8. **Beads issue prefix is `kb`.** Short, unambiguous, does not collide with the `bd`
   command name.

## 2026-09-10 · protocols and evolution · decisions made without asking

9. **`docs/protocols/` and `docs/integration/` are new directories**, not in brief section
   11. Wire contracts are specs, not decisions, and they were being written into ADRs where
   they did not fit. Recorded in `docs/DEFAULTS.md` under Protocols, and in `AGENTS.md`
   section 7.

10. **Five extension URIs under `https://kourob.org/ext/`**, one per KNP spec, rather than
    one omnibus extension. Per-spec URIs let a caller activate provenance without activating
    metering, which is the common case for a read-only client. Cost: five URIs to keep
    alive instead of one.

11. **`kourob.org` is assumed as the extension namespace and is not registered.** ADR-0006
    notes this. The URIs are opaque identifiers and nothing dereferences them today, so this
    is not blocking — but it becomes a real problem the moment a third party implements
    against them. Registering the domain, or moving to `w3id.org`, is a human decision.

12. **The evolve objective is cost per *settled* request** (ADR-0007), which is a stronger
    claim than the brief makes. The brief's cost-per-request target in `GOAL.md` is
    unchanged; the denominator is now narrower, so the target is harder, not easier. If this
    turns out to make the 5x target unreachable, the honest fix is to report both numbers,
    not to widen the denominator.

13. **A T0 rule needs exact replay, not a tolerance** (ADR-0008). This will slow the cost
    curve. It is the price of `derived` meaning what it says.

## 2026-09-10 · running infrastructure · decisions made without asking

14. **`src/kourob/node.py` and `src/kourob/serve.py` are new modules**, not in brief §11.
    `init`, `ingest`, `query`, `doctor`, the MCP port and the REST port were each about to
    assemble the same four objects — manifest, store, gate, ledger — in the same order.
    `node.py` is that assembly; `serve.py` is the one place an answer is built, so it is the
    one place the KNP-0 invariants can be enforced.

15. **A fourth determinism class, `declared`.** Found by a test: `list_schemas` returns the
    node's own contracts, which are not derived from events and have nothing to cite.
    KNP-0 I2 needed an exemption for **introspection** — a node reciting its own signed
    declaration — distinct from the refusal exemption. Narrow on purpose: it covers the node
    describing *itself*, never the node describing anything else.

16. **A small ODCS reader now, `datacontract-cli` later.** `schema/loader.py` covers the
    subset the gate needs (required, logical type, enum, range, pattern). Shipping it first
    means the gate can be built and measured today, and it is replaceable because nothing
    outside that module knows the file format. Codegen and breaking-change detection stay
    on kb-4m5.

17. **`kourob init` ships a working starter** — `note.v1`, a T0 rule, and fixtures including
    deliberately bad lines. Without it, `kourob init && kourob ingest fixtures/events.jsonl`
    from brief §12 M1 cannot run, and GOAL.md metric 1 ("under 10 minutes to a cited
    answer") is not testable.

18. **The zone-path rail moved from `gate.py` to `store/parquet_duckdb.py`.** The rail's
    intent is "nothing reaches around the Store"; the Store backend obviously names the
    paths it maps. Only-gate-writes-silver is now checked by the gate's own tests rather
    than by grep, because grep cannot see a call.

19. **`Store.query` accepts named parameters.** A mined T0 rule binds from named capture
    groups, and making generated SQL depend on positional order is a bug waiting for a
    rule with two parameters in the wrong sequence.

20. **A T0 rule that matches the question but finds no rows is a miss, not an empty
    answer.** Silence is not a fact. The cascade falls through instead of returning
    "nothing", which would be a claim.

## 2026-09-10 · runner and outcomes · decisions made without asking

21. **The scripted mock and the real local adapter are one class.** A test that scripts
    replies exercises the same logging, pricing and validation path production runs. A
    separate mock object would let those drift, and the drift would be invisible until a
    cost number was wrong.

22. **An unscripted call in a test raises rather than returning something plausible.** A
    test that reaches the model without meaning to is asking a question it did not intend
    to ask, and a plausible answer hides that.

23. **A failed model call is logged before it is re-raised.** A node that only remembers its
    successes cannot know its own reliability, and reliability is route-table input.

24. **Estimated token counts are labelled** (`tokens_estimated`). A cost curve computed from
    estimates must be distinguishable from one computed from measurements, or the headline
    5x number means nothing.

25. **T3 declines rather than answering ungrounded.** If every citation a model returns is
    absent from silver, the tier misses. Emitting it would launder a guess into the
    provenance graph, which KNP-2 §5 names as the worst failure the protocol can have. A
    mix of real and fabricated citations answers on the real ones and halves confidence.

26. **`settle_key` is hashed, and it is a new signed receipt field.** Without it a later
    fact cannot find the answers it settles. Hashed because a receipt may be published and
    its subject may not be. Adding it to `SIGNED_FIELDS` is a breaking ledger change, taken
    now while the format is unreleased.

27. **`unresolved` is computed, never written.** Appending a record to say that nothing
    happened would manufacture evidence out of its own absence. The chain is for facts.

28. **The chain is ordered by an explicit `seq`, not by id.** Ids are `<prefix>_<ULID>` and
    `outc_` sorts before `rcpt_`, so id ordering broke `prev` the moment a node recorded its
    first outcome. Found by a test, not by reading. `seq` is unsigned: reordering breaks
    `prev`, and `prev` is the integrity mechanism.

29. **A stranger's outcome is downgraded, never refused.** A third party noticing an error
    is useful even when it cannot be trusted, so it lands at `source: caller` weight 0.25.

30. **A correction must name what was true.** `verdict: corrected` with no evidence is
    refused: saying an answer was wrong without saying what was right teaches nothing, and
    the whole point of an outcome is that it is a training label.

## 2026-09-10 · clustering and evolve · decisions made without asking

31. **`src/kourob/request_log.py` is a new module**, not in brief §11. The request log is
    separate from the ledger on purpose: a receipt is published and stores hashes, a request
    row is local and stores the question — because you cannot cluster demand you cannot read.

32. **A cluster key is the decision path for an answered request and the question frame for
    a refused one.** A refusal has no decision path, and refusals are the most informative
    rows in the log.

33. **The question shape keeps the frame and drops the subject.** "what is a bridge" and
    "what is a cell" share a shape. The opposite — keeping the subject — looks like
    clustering and is not: every topic becomes its own cluster.

34. **`Ledger.extend` batches a chained append.** `append` re-reads the chain to find its
    predecessor, which is fine for one record and quadratic for a thousand. Found by a
    fixture that hung.

35. **The Store pads every batch to the union of its rows' keys.** `pa.Table.from_pylist`
    infers a schema from the first record, so a batch of receipts followed by outcomes
    **silently dropped every outcome field**, leaving signatures over data that was no
    longer there. This was a data-loss bug and it was silent.

36. **A schema that settles other schemas is never shed**, nor is one being written. A shed
    rule that counts only reads will eventually delete a node's ability to improve.

37. **Split proposals carry a real child manifest**, not a description of one. A reviewer
    should read the child's scope, inherited tiers and autonomy level rather than imagine
    them. The child resets to A0: autonomy is earned by evidence and a child has none yet.

38. **`kourob loop run evolve` is implemented; the other five loops still exit 2.** `loop
    list` says which is which rather than presenting six equal-looking names.

## 2026-09-10 · connect · decisions made without asking

39. **The first transport is a path, not HTTP.** `kourob connect ./cell` and a bridge that
    opens the neighbour by directory. The whole loop — scope check, referral, bridge,
    chained receipts, route learning, hop refusal — was untested against a second party
    until it could be tested with two directories and no server. HTTP attaches behind the
    same `Neighbour` contract. A URL endpoint is refused, not guessed at.

40. **`docs/STATUS.md` is a rewritten-not-appended file.** It says where the project *is*
    against `GOAL.md`; the handoffs say how it got there. Two kinds of record, two files.

41. **Bridge introductions are counted from the request log**, not a separate table. A
    bridge is a request, and the log already records who asked and where it went.

42. **A route update is an appended row and the latest wins.** Wasteful, auditable, and
    the right trade for a table that decides where money goes.

43. **A referral after a cascade miss carries the route's evidence receipt** and names
    `rule:route-match`, because it rests on the route table's guess rather than the node's
    declaration, and the caller is entitled to weigh it lower.

44. **A learned route starts at strength 0.4; a connected one at 0.5.** Hearsay starts
    weaker than something the operator chose, and one success on either raises it the same.

45. **The scope check runs before any tier, and the route table is consulted again only
    after a cascade miss.** Declared exclusions are the node's contract; the route table is
    its guess. The receipt records which decided.

## 2026-09-10 · rule mining · decisions made without asking

46. **Exact replay compares cited event sets**, not rendered text. It is what `derived`
    promises a stranger — the same events — and it is checkable from the request log today.
    Comparing text needs the log to keep it; follow-up.

47. **Rungs may be skipped downward to T0.** Exact replay is a stronger gate than any
    tolerance rung; the no-skip rule exists to stop tolerance shortcuts, of which T0 has
    none. Written into KNP-5 §3.3.

48. **One frame per mined rule.** Python's `re` forbids a group name twice, and `Rule` has
    one pattern. Minority frames go uncovered and count against coverage.

49. **A binding field must match on every settled request whose subject names any field.**
    Requests whose subject names nothing are the rule's declined tail and count against
    coverage; a request whose subject names a *different* field disqualifies the binding.
    First written as "every request", which rejected the very cluster the edge-case eval
    was built to prove partial coverage on. The replay gate, not the binding search, is
    what keeps a coincidence out of T0.

50. **Demotion of a T0 rule is the one change evolve makes itself.** One `corrected` outcome
    renames the rule file to `.yaml.disabled` in the same run. It withdraws a privilege whose
    evidence stopped holding — the same mechanism as an autonomy demotion — and it is
    trivially reversible. Everything else the loop does is a proposal.

51. **Promotion thresholds are overridable from `manifest.loops.evolve`** (`n_rule` today).
    A fixture with eight settled requests should not need two hundred to prove the miner.

## 2026-09-10 · tend · decisions made without asking

52. **A change is a `node_change.v1` event pushed through the gate.** The gate is the only
    silver writer, and a change the node made to itself is a fact like any other. The
    contract is infrastructure and does not count against the schema ceiling.

53. **Graduation is suggested, never set.** `tend` names the next level after
    `graduation_window` clean cycles; the operator writes it. Demotion is automatic,
    immediate, and recorded as an `autonomy` change carrying its inverse.

54. **A split and any scope change are proposals at every level.** A split creates a cell
    and has no inverse worth the name; scope widening is the one thing autonomy never
    includes (KNP-7 §1).

55. **Halts that would fire on a brand-new node do not.** Quality below `q_floor` halts only
    once something has settled; settle-rate below floor only once twenty receipts exist.
    A node with no history is not failing, it is new.

56. **Rolling back a rollback is legal and counts as a rollback.** Two in a row halt, per
    KNP-7 §4.2: the evidence gates themselves are suspect.

## 2026-09-10 · MCP server · decisions made without asking

57. **The transport is a separate file from the handler.** `ports/mcp.py` answers and
    knows nothing about stdio; `ports/mcp_server.py` speaks stdio and knows nothing about
    answering. Both stay under the 300-line port ceiling, and the SDK import stays lazy so
    `import kourob` never needs the extra.

58. **`kourob attach` writes a project-scoped `.mcp.json`** in the cell for claude-code and
    cursor, and prints a TOML fragment for codex. Idempotent: attaching twice updates one
    entry. Attaching to a *node* is refused and pointed at `kourob connect`.

59. **Tools return the envelope as structured content.** An agent gets `receipt_id` and
    `citations` as fields it can act on, not prose it has to parse.

60. **The MCP test spawns the real server process** and speaks the real protocol to it.
    A test against an in-process fake would prove the fake.

## 2026-09-10 · metering · decisions made without asking

61. **Affordability is checked against the ceiling, not the price.** The cascade's
    uncertainty is the node's risk, not the caller's (KNP-3 §2), so a caller is refused
    only if it could not cover the worst case — and never after work has started.

62. **The price on a receipt is capped at the ceiling the pricer would have quoted**,
    recomputed at answer time from the same window and the same quality. A node must not
    charge above what it quoted, and the cap is how that promise survives a cascade that
    fell further than expected.

63. **A quote predicts T0 when a rule binds**, whether or not the SQL then finds rows. The
    quote predicts; the ceiling protects. Running T0 to predict would be cheap, and is a
    refinement for when T0 misses are common enough to matter.

64. **Debits are post-paid and balances may go negative.** The free allowance is what stops
    a stranger running one up, and refusal is upstream of the accounts table. Every movement
    is an appended row; a balance is a sum on read.

65. **An unmeasured node prices at `q_min`.** The quality multiplier is earned from settled
    outcomes; with nothing settled it is 0.5, and one accepted answer lifts it. A node
    nobody checks cannot charge a premium for answers nobody checked.

66. **`ledger/meter.py` is a new module.** The report is where measured cost and computed
    price meet as a number an operator reads, and `margin` is the quantity KNP-7 makes
    autonomy depend on.

## 2026-09-10 · compile and lint · decisions made without asking

67. **Page metadata is a comment, not a sentence.** "Schema note.v1, 6 claims" describes the
    page, not the world, and the linter flagged it as an uncited claim — correctly. The
    compiler now writes non-claim text as HTML comments and the scope summary into the
    heading, and the linter needs no special cases for the index beyond "a link is not a
    claim". Found by running lint over compile's own output.

68. **Compile owns what it generated and nothing else.** A generated page nothing produces
    any more is removed; a hand-written page is left for lint to flag as `hand_edited`.
    Silently deleting someone's work is worse than telling them it cannot stay.

69. **A citation is any `[evt_...]`, not a ULID-shaped one.** Whether the id exists is
    lint's `orphan_citation` check, which is a more useful flag than "wrong length".

70. **`tend` halts on a lint failure.** An uncited claim on a page is a build failure
    (KNP-2 §5), and nothing autonomous should run on top of a knowledge base lint would not
    pass. Compile runs first, so a hand edit to a *generated* page is simply overwritten;
    only a hand-written page can halt.

71. **Grouping is by the contract's first key field.** `note.v1` pages by topic; a contract
    with no key fields gets one page. Good enough for the starter and for the dogfood node;
    a real cell will want to declare its page key explicitly.

## 2026-09-10 · dogfood · decisions made without asking

72. **The file in-port is markdown-to-notes.** Every paragraph under a heading becomes a
    `note.v1` push with `source = file#heading`, so a citation resolves to a place in the
    docs, not just an event id. Code fences and tables are skipped: they are reached through
    the file the note names, not restated as sentences. Paragraphs under 40 characters are
    fragments, not claims.

73. **`examples/kourob-node` commits nothing generated.** Keys are secret, Parquet is binary,
    pages are derived. The README is the recipe and `tests/test_dogfood.py` builds the node
    from scratch on every run and answers the M2 question from this repository's own words.

74. **The dogfood answer runs at T3 with a scripted grounded model in the test.** Heading
    slugs ("5-bridging") do not equal question subjects ("bridge"), so T0 does not bind;
    retrieval by keyword overlap finds the bridging paragraphs and the cited event's body
    is checked to be about bridging. A real local model gives the same path unscripted.

## 2026-09-11 · T1 and the cost curve · decisions made without asking

75. **The student is a nearest-settled-answer model, not a neural net.** Every settled,
    accepted answer is an example: content tokens, question frame, cited events, decision
    path. A new question is matched by token overlap within the same frame and answered from
    that example's events. No weights: a JSON file, deterministic, explainable, and three
    orders of magnitude cheaper than the frontier call. At this scale a LoRA would be a
    dependency in search of a problem; the tier interface is what a real one attaches to.

76. **Gold is a store table, written only by the gate, read only to score.** `train.py` joins
    requests with outcomes and never touches it; `calibrate.py` reads it by logical table
    name. The rail that training code names no gold path holds by construction.

77. **The student's label is the rule path's decision, not the answering tier.** `rule:<id>`,
    `t3` or `refuse` — the class it is scored on against gold, the same for a lookup a rule
    caught and a paraphrase a model answered. T0-caught examples are kept: T0 runs first so
    the student never answers them, but it must know they exist to place the boundary.

78. **The bar is calibrated per class, lowest bar that hits the target on every class.** A
    class the student is never confident about is not a failure; it is work left to the
    tiers above. Matching on aggregate while collapsing a class is the classic distillation
    failure, and the average would hide it.

79. **T1 is enabled by `enable`, and `enable` refuses without gold.** The cascade constructs
    the tier only when the manifest says enabled, and only `enable` sets that — so a T1 in
    the cascade is a T1 that was checked against something other than its teacher. `tend`
    proposes rather than applies a T1 promotion on a node with no gold.

80. **The ladder skips a disabled T2 with the stricter gate carried down.** A node without T2
    goes T3 to T1 and needs T1's thousand settled examples, not T2's fifty. Skipping a tier
    is fine; skipping its evidence is not. T1 itself is never skipped: it is disabled until
    promoted to, which is what the promotion does.

81. **T0's cost is a SQL scan, not its price.** `cost_credits` on a T0 answer was
    `base_cost[T0]`, which is a price. Conflating them hid the curve: a rule that "costs" its
    price can never look cheaper than its price. Measured cost is now a constant per scan;
    the pricer applies the price.

82. **`Ledger.head` reads one row.** `append` needs only the newest record, and reading the
    whole chain to find it made every answer O(n) in the node's history — invisible at a
    hundred receipts and the first thing a thirty-day replay ran into.

83. **The pricer reads quality from the last evolve report.** KNP-3 §3 says quality is
    computed over a trailing window; the evolve cycle *is* that computation, done once.
    Recomputing it from the whole ledger on every request made each answer O(receipts):
    a thirty-day replay spent most of thirty-six minutes decoding the chain to price a
    lookup. With no report yet, it is computed once per pricer.

84. **A month-long caller in the replay is funded.** The first replay forgot this: the
    free allowance ran out on day one and every request after was refused for credit, so
    the curve measured a node saying no at no cost — T0+T1 share 0.00, and the eval
    failed for the right reason. A caller that asks two hundred times a day pays.

85. **The store re-registers a view only when its part list changed.** Every query was
    re-globbing seven directories and rebuilding seven views. Per-table signatures make a
    query over an unchanged table free; compaction resets them.

86. **Four per-request costs found by profiling two hundred requests, not by reading.**
    `stats` opened every Parquet part's footer to count rows (fifty thousand constructions);
    now one DuckDB count, cached until the store writes. `Node.contracts` re-parsed every
    YAML on every access; now once per opened node. `load_rules` re-parsed rule YAML per
    request; now cached by file mtimes. And the accounts table gained one part per paid
    request and was never folded — the store now compacts any table past sixty-four parts
    on its own, so no caller has to remember to.

87. **Quality is recomputed every two hundred receipts, not every request** — from the
    last evolve report when one exists, else from a small cache under `logs/`. A young node
    (under two hundred receipts) recomputes every time: its chain is tiny and every outcome
    moves the number. KNP-3's "trailing window" was always a periodic computation; doing it
    per request was the bug, not the spec.

88. **The replay starts with T1 off.** The fixture warms and enables the student so it can
    be scored against gold; the cost curve must begin where a real cell begins, so the
    replay disables it and lets the weekly `tend` bring it back.
